# Website 9.0v Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox tracking. Recommended execution: native in this chat, with review at each phase. No execution method has been selected yet.

**Goal:** Deliver an AI-first portfolio, blog, and resume on GitHub Pages, maintained through browser forms and uploads.

**Architecture:** Root-level Astro generates static HTML from validated Markdown and JSON. Hosted Pages CMS edits repository files. GitHub Actions validates and deploys successful artifacts; deployment remains disabled during development.

**Tech Stack:** Astro, TypeScript, CSS, Pages CMS, GitHub Actions; Vitest for behavioral checks, Cheerio for generated HTML verification. No Angular/React runtime at launch.

**Spec:** `docs/superpowers/specs/2026-10-03-website-9-design.md`. Read this and `docs/migration/legacy-inventory.md` before execution.

## Global Constraints

- Branch exactly `9.0v`; source baseline `e5bd23b0df82a124b67a342bac011570e0c16570` from freshly fetched `world-7.1v`.
- Public site `https://ani-poroorkara.github.io`; static output; trailing-slash pages; no repository base prefix.
- Node 24 locally/CI; exact direct dependency versions; committed lockfile; CI uses `npm ci`.
- Content field names, enums, validation, media limits, colors, widths and accessibility behavior are defined in the spec and apply to every task.
- Draft default true; exclude draft/future content from routes, lists, sitemap and RSS; America/Toronto build date; stable filename slugs.
- Deployment only on `9.0v` push/manual dispatch with `PAGES_DEPLOY_ENABLED=true`; never on PRs or draft-preview output.
- No invented resume/project claims. Empty authoring data is allowed; verified resume facts are required before launch.
- Browser editor is hosted separately; no authentication server/API secrets in the public site.
- No chatbot, newsletter, CMS MDX, theme toggle, automatic GitHub importer, or automatic PDF regeneration.
- Source cleanup already completed; assets/content are recovered selectively from the baseline commit, not by restoring the old application.

## Review Focus

1. CMS serializes empty optional fields as null/empty strings: normalize these consistently, reject wrong types, and keep filename identity stable after a title edit (Tasks 2, 5).
2. Calendar dates at midnight/DST or invalid leap days: date validation and filtering must never shift publication by timezone (Task 2).
3. Drafts and future content accidentally leak into a route/feed/sitemap: a single publication rule and built-output checks must cover all destinations (Tasks 3, 8).
4. Uploads have missing files, unsafe paths, mismatched format or excessive size: reject with a useful file/field message before deployment (Tasks 4, 5).
5. First-time editor use, no published posts, no resume PDF or inaccessible mobile navigation: show useful empty states and complete browser journeys (Tasks 3, 7, 11).
